1. 발표 시 가능하면 기술적 용어를 사용합니다.
   (틀린 예: 클릭하면 댓글 목록을 가져옵니다.)
   (바른 예: 클릭하면 fetch 함수를 이용해 컨트롤러로 비동기 요청을 하고...)

2. 간단한 시연이 끝나면, 트러블 슈팅 및 회고 시간을 가집니다.
   1) 트러블 슈팅(어떤 문제가 발생, 어떻게 해결, 해결을 위해 찾아본 내용 등)
   2) 회고(진행하면서 느낀 점, 앞으로 공부해야겠다고 생각한 분야 등)

--------------------------------------------------------------------------------------------

1. 공통 상단(Header) 
모든 페이지 상단에 로고와 사용자 닉네임이 출력
닉네임은 HttpSession에 저장된 userId를 기반으로 Controller에서 DB를 조회한 뒤, 세션 속성에 닉네임을 저장하고 JSP에서 출력

2. 쪽지 작성 페이지
입력 검증: onSubmit 이벤트에서 닉네임과 제목이 비어 있으면 alert를 띄우고 submit을 중단
취소 버튼: <button type="button">으로 구현 onclick=주소(storeType 값)에 따라 보낸함 또는 받은함으로 돌아감
보내기 버튼: 클릭 시 POST 요청으로 MessageDTO가 컨트롤러에 전달
서비스 계층에서 DB에 insert 후 성공 시 FlashAttribute에 메시지를 담음
JSP에서 alert로 성공 메시지를 보여주고, 해당 쪽지함으로 redirect 됨

3. 선택 삭제 기능 (다중/전체 삭제)
<input type="checkbox">의 messageId 값이 List<Integer> messageIds로 컨트롤러에 전달
삭제 후 개수를 FlashAttribute로 전달해 JSP에서 alert로 표시

4. 페이지네이션 기능
PageDTO와 PageUtil을 통해 
현재 페이지, 한 페이에 표시할 항목의 개수,전체 아이템 개수 -> 각 페이지의 시작 인덱스, 전체 페이지 개수, 시작 페이지 번호, 끝 페이지 번호를 계산
JSP에서는 <c:forEach>와 EL을 활용해 페이지 번호 버튼을 동적으로 생성
현재 페이지는 CSS 클래스(focus-page)로 강조
이전/다음 페이지, 이전/다음 블록 이동 버튼도 제공
<select> 박스로 페이지 당 항목 개수를 선택할 수 있고, 변경 시 JavaScript로 GET /ms/receiveStore?page=1&size=value 요청을 보냄

5. 쪽지함 테이블 (받은/보낸 쪽지 목록)
제목 칸은 <a> 태그를 <td> 전체에 덮어씌워 셀 전체를 클릭하면 상세보기로 이동하도록 만듦

6. 쪽지 상세 페이지 (messageDetail.jsp)
Controller에서 messageId를 검증
null, 빈 값 / 잘못된 숫자 형식 / DB 조회 결과가 없을 경우 → 오류 메시지를 FlashAttribute로 전달하고 목록으로 redirect

7. 삭제 및 답장 기능 (상세 페이지)
삭제 버튼: <form>으로 POST 요청을 보냄
실행 전 confirm 창을 띄워 messageId가 유효 시 삭제 진행, 취소 시 요청 중단
삭제 성공 → FlashAttribute에 “삭제 완료” 메시지를 담아 목록으로 redirect
답장 버튼: 클릭 시 GET요청을 보내고 보낸 사람 닉네임이 자동으로 입력된 상태로 작성 페이지가 열림
파라미터로 senderNickname

8. 탈퇴한 유저 표시
MyBatis Mapper에서 CASE WHEN 조건문
 deleted_at  있으면 닉네임, 없으면 IS NOT NULL THEN '(탈퇴한 유저)' ELSE nickname END 구문을 사용
